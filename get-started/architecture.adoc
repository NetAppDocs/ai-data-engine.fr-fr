= Architecture de l'AI Data Engine
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
AI Data Engine (AIDE) s'exécute sur l'infrastructure que vous fournissez. Le Metadata Engine analyse votre stockage et crée un catalogue interrogeable. NetApp Console gère votre déploiement via un agent Console. Une option de serveur Model Context Protocol (MCP) permet aux clients d'IA de rechercher dans le catalogue dans les limites que vous définissez.



[[components]]
== Composants

Le tableau de bord, les investigations et les politiques de AI Data Engine dans NetApp Console fonctionnent tous à partir du catalogue de métadonnées. Les composants suivants constituent le catalogue, le connectent à NetApp Console et fournissent un accès contrôlé aux clients IA.



[[metadata-engine]]
=== Metadata Engine

Le Metadata Engine est la fonctionnalité principale de AI Data Engine. Il analyse les sources de données que vous connectez, extrait les métadonnées et les stocke dans un catalogue consultable. Il ne lit ni ne classe le contenu des fichiers. Le Metadata Engine met à jour le catalogue à chaque cycle d’analyse, détectant les ajouts, les modifications et les suppressions sur vos systèmes de stockage.



[[netapp-console-agent]]
=== Agent NetApp Console

AI Data Engine nécessite le déploiement d’un agent NetApp Console dans votre environnement. L'agent Console est un composant polyvalent de la plateforme NetApp qui maintient la connectivité entre votre environnement et NetApp Console. Il gère l'authentification et la communication entre NetApp Console et votre déploiement AI Data Engine. Les services d'analyse et de catalogue s'exécutent dans votre déploiement AI Data Engine, et non sur l'agent Console.


NOTE: L'agent Console n'est pas spécifique à AI Data Engine. Si vous avez déjà déployé un agent Console pour d'autres services NetApp, vous pouvez utiliser le même agent. Pour obtenir des instructions sur le déploiement de l'agent Console, consultez la link:https://docs.netapp.com/us-en/console-setup-admin/concept-agents.html["Documentation de l’agent NetApp Console"].



[[governed-access-gateway]]
=== Passerelle d'accès gouvernée

La passerelle d'accès gouverné est le serveur MCP pour AI Data Engine. Elle permet aux clients AI de rechercher dans le catalogue de métadonnées. La passerelle s'exécute dans votre déploiement AI Data Engine, et les clients AI s'y connectent via HTTPS depuis votre réseau d'entreprise ou par VPN. L'agent Console ne relaie pas le trafic MCP.

Microsoft Entra ID authentifie les utilisateurs, et la passerelle limite chaque client AI aux collections que l’utilisateur est autorisé à rechercher. La passerelle prend en charge uniquement la recherche et l’étiquetage des métadonnées, et seuls les utilisateurs avancés peuvent étiqueter les fichiers. Elle ne récupère pas le contenu des fichiers.

link:../mcp/learn-about-mcp.html["Apprenez-en davantage sur l'accès gouverné à l'IA"].



[[deployment-types]]
== Types de déploiement

AI Data Engine prend en charge deux types de déploiement. Les deux exécutent les services AI Data Engine sur Kubernetes.

Déploiement AIDE sur un seul nœud:: S'exécute sur une seule machine virtuelle Linux que vous fournissez. Le programme d'installation provisionne automatiquement k3s et les composants nécessaires. Un déploiement sur un seul nœud ne garantit ni la haute disponibilité ni la mise à l'échelle horizontale.
Déploiement multi-nœuds d'AIDE:: Fonctionne sur un cluster Kubernetes que vous fournissez et est conçu pour des environnements plus vastes nécessitant une haute disponibilité.


Pour connaître les plateformes prises en charge, le dimensionnement et les exigences d’infrastructure, consultez link:../deploy/aide-requirements.html["exigences AIDE"].

Chaque type de déploiement possède également une procédure distincte pour les environnements qui accèdent à Internet uniquement via un proxy sortant. Reportez-vous à link:../deploy/configure-proxy.html["Découvrez les proxies pour AI Data Engine"].

link:../deploy/deployment-overview.html["En savoir plus sur les options de déploiement"].



[[data-flow]]
== Flux de données

AI Data Engine utilise deux chemins distincts : l’un qui crée le catalogue et le met à disposition de NetApp Console, et l’autre qui dessert les clients AI.



[[metadata-scanning-and-netapp-console-access]]
=== Analyse des métadonnées et accès à NetApp Console

. Vous déployez AI Data Engine sur une infrastructure que vous gérez et la connectez à un agent NetApp Console.
. Vous connectez les sources de données que vous souhaitez voir cataloguer par AI Data Engine dans *Sources de données*. Pour plus d'informations, consultez link:../data-sources/connect-data-source.html["Connectez une source de données"].
. Le Metadata Engine analyse les sources de données pour extraire les métadonnées et les indexe dans le catalogue.
. Dans NetApp Console, le tableau de bord affiche des informations sur le stockage issues du catalogue, et Investigation vous permet d'interroger directement le catalogue à l'aide de filtres de métadonnées.
. Vous pouvez enregistrer les critères de recherche sous forme de stratégies et les réexécuter pour identifier les fichiers correspondants, et vous pouvez agir sur les fichiers depuis Investigation.



NOTE: Le catalogue reflète les métadonnées collectées lors de l'analyse. Les modifications apportées aux fichiers sources apparaissent dans le catalogue une fois que les fichiers et répertoires concernés ont été analysés à nouveau et que les résultats ont été indexés.



[[governed-ai-access]]
=== Accès gouverné à l'IA

. Vous configurez Microsoft Entra ID, activez les collections pour l’accès à l’IA et choisissez les utilisateurs autorisés à effectuer des recherches dans chaque collection.
. Un utilisateur connecte un client d’IA au point de terminaison HTTPS du Governed Access Gateway et se connecte avec Microsoft Entra ID.
. La passerelle vérifie l'accès de l'utilisateur et transmet les requêtes autorisées au Metadata Engine.
. Le client IA recherche les métadonnées dans les collections auxquelles l'utilisateur peut accéder et sur lesquelles il peut effectuer des actions.
